# 패키지 화면 하나 — 콘솔 상세와 스튜디오를 합친다

2026-08-26 · 앞선 문서: `2026-08-26-package-describe-design.md` (1층 "읽기", 완료)

## 왜

콘솔 상세(설치본)와 스튜디오(draft)는 같은 패키지를 두 화면에서 보여준다. 분리의 실제 축은
live/draft 였지 읽기/쓰기가 아니었고, 비개발자에게는 "같은 게 왜 두 군데 있지"로 보인다.
1층(설명서)이 콘솔에 들어갔으니, 이제 스튜디오의 나머지 두 층을 같은 화면으로 옮긴다.

## 결과 모습

`/?p=<이름>&face=detail` 하나가 패키지 화면이다. 세 층:

```
머리   아이콘 · 이름 · 버전 · [상주|상세] · 화면 열기
       ── draft 가 열려 있으면 ──  ↶ ↷ · ＋ 만들기 · 검사 · 기록 · [적용] · ⋯(이전 판으로 / 작업 사본 버리기)
       ── 아니면 ──                고치기
몸     소개 한 줄 + 칩 (수정 n건 · 아직 적용 안 됨 / 변경 없음)
       설명서 줄들 (1층) — 어느 줄이든 누르면 그 줄 아래로 펼쳐진다 (2층)
         펼침 = 왼쪽 그 섹션의 기존 폼(SectionView) · 오른쪽 결과면(Preview, 재료별)
         폼의 파일 카드를 누르면 몸 전체가 에디터가 된다 (3층) — 상단에 "◀ 돌아가기 · 경로 · 삭제"
       콘솔 띠 (검사 결과·기록·적용 로그, 접힘)
       하단: 데이터 폴더 열기 · 제거
```

- **live 냐 draft 냐**: draft 가 있으면 draft 를 보여주고 칩으로 그 사실을 말한다. 없으면 설치본.
  줄을 누르거나 [고치기]·[만들기]를 누르면 draft 가 열린다(설치본 사본). 콘솔 목록(사이드바·설정
  지도)은 그대로 설치본이다.
- **설치 안 된 draft** (만드는 중)도 같은 주소로 연다 — 장부에 없으면 draft 목록에서 찾아
  매니페스트를 draft 에서 읽는다. 머리의 버전은 "미발행".
- **새 패키지**: `/?new=1` 에 마법사(스튜디오의 Wizard 그대로), 만들면 `/?p=<이름>&face=detail`.
- `/studio/` 는 리다이렉트만 남는다: `?pkg=x&sec=&item=&file=` → `/?p=x&face=detail&sec=&item=&file=`,
  `?new=1` → `/?new=1`, 나머지 → `/`.
- 사이드바(기판 `runner/runtime/shell.ts`): "패키지 만들기" → `?new=1`, 초안 각각 →
  `?p=<이름>&face=detail`, "만드는 중 N" → 셸 홈(초안 띠가 거기 있다). 홈의 "스튜디오에서 이어서
  만들기" 링크는 없앤다 — 이름마다 이미 문이 있다.

## 설명서 줄 (1층) 확장

모든 선언 섹션이 줄 하나씩 갖는다 — 2층으로 가는 문이 줄이므로, 줄이 없는 섹션은 고칠 수 없다.

| key | 질문 | sec |
|---|---|---|
| identity | 이름과 버전 | identity |
| verbs | 시킬 수 있는 일 | scripts |
| when | 스스로 움직이는 때 | triggers |
| dirs | 손대는 폴더 | services |
| talk | 대화하는 곳 (이 화면 · 에이전트들) | agents |
| faces | 화면과 채널 (view · 끼울 부품 · 채널 이름) | surfaces |
| links | 바깥 연결 | edges |
| missions | 맡길 수 있는 일 | missions |
| engine | 동작 엔진 | harness |
| needs | 필요한 것 | requires |
| (고급, 접힘) host | 기판 기능 허용 | host_methods |
| (고급) org | 조직 설정 | org |
| (고급) files | 기타 파일 n | files |

draft 가 열려 있으면 빈 줄도 전부 보인다("아직 없음" — 누르면 거기서 만든다). 설치본만 볼 때는
지금처럼 engine·needs·고급 줄은 비면 생략.

## 구조

### 1단계 — 스튜디오 기계를 훅으로 (UI 무변화)

`app/studio/page.tsx` (842줄) 의 상태와 동작 전부를 `lib/useDraft.ts` 로 옮긴다:

```ts
export function useDraft(pkg: string | null, view: { sec, item, file }, nav: (q) => void): Draft
```

`Draft` 가 주는 것: `status · fatal · manifest · schema · buf · issues · verdicts · marks · log ·
conflict · agentBusy · undo/redo 길이 · effFile · rev · ctx(SectionCtx) · previewCtx(PreviewCtx)` 와
동작 `open() · refresh() · onEdit() · writeManifest() · stepHistory() · validate() · pack() ·
onPublished() · conflictReload() · conflictOverwrite() · deleteFile() · say() · seedHarness()`.
`fixTargetOf` 는 `lib/verdict.ts` 로. page.tsx 는 훅을 부르고 그리는 껍데기가 된다.
이 단계가 끝나면 스튜디오는 **그대로** 돈다 — 굽고 눈으로 확인한다.

새 훅의 한 가지 차이: `pkg` 가 있어도 **자동으로 draft 를 열지 않는다**. `open()` 을 불러야 연다.
스튜디오 page 는 진입 즉시 `open()` 을 부른다(지금과 같은 행동). 패키지 화면은 draft 가 이미
있을 때만 `open()` 을 부르고, 없으면 사용자가 줄·고치기·만들기를 눌렀을 때 부른다.

### 2단계 — 패키지 화면

- `components/DetailFace.tsx` (PkgPane 에서 분리): 설명서 + 펼침 + 에디터 + 콘솔 띠 + 하단.
  `useDraft` 를 쓴다. URL 의 `sec · item · file` 이 펼침·에디터의 정본(스튜디오 규약 그대로).
- `components/Describe.tsx`: 줄이 링크가 아니라 버튼이 된다. `expanded` 줄 아래에 `children`.
- `components/DraftActions.tsx`: 머리의 버튼 묶음 + 다이얼로그(StudioDialogs 재사용) + ⋯ 메뉴.
- `components/EditorPanel.tsx`: 돌아가기 줄 + 충돌 배너 + CodeEditor.
- `components/DraftConsole.tsx`: 스튜디오의 콘솔 띠 그대로.
- `app/page.tsx`: `?new=1` 이면 Wizard. `p` 가 장부에 없으면 draft 목록을 보고 draft 전용 Pkg 를
  합성한다(`workspace: ""`, `harness: null`, manifest 는 draft 의 것).
- `app/studio/page.tsx`: 리다이렉트만.
- 지우는 것: `DeclTree.tsx`, 스튜디오 셸 CSS(`.st-shell · .st-top · .st-body · .st-tree · .st-node …`).
  폼·파일 카드·콘솔 CSS(`.st-form · .st-field · .st-files · .st-console …`)는 남는다.
- `lib/describe.ts`: 위 표대로 줄 확장. `describe(m, ctx, { editing: boolean })`.
- 기판 `runner/runtime/shell.ts`: 링크 셋만 바뀐다.

### 에러 · 경계

- draft 열기 실패(`fatal`)는 몸 상단 배너. 줄은 설치본으로 남는다.
- 동시 편집 충돌은 지금 스튜디오와 같은 배너·두 처분.
- 설치 안 된 draft 는 "상주" 탭이 없고 "제거" 대신 "작업 사본 버리기"(⋯ 메뉴)만 있다.
- 제거 확인 문구는 그대로.

## 덧: 세 칸 — 쓰면서 고친다 (2026-08-26 저녁)

위 "결과 모습"은 고치는 화면만 있고 **써보는 자리가 없었다**. 에이전트를 써보려면 "화면 열기"로
새 브라우저 탭에 가야 했고, 상세를 여는 순간 콘솔 채팅이 빌더로 바뀌어 패키지 에이전트와는
말할 수 없었다. 그래서 패키지 화면을 세 칸으로 편다(탭 없음):

```
머리     아이콘 · 이름 · 버전 · (draft 버튼들) · [구조|상주] · 화면 열기
왼쪽     설정 패널 — 위의 1·2층(설명서 줄, 누르면 폼) 을 420px 칸에. 질문 위·답 아래로 쌓는다
가운데   실제 화면 — /pkg/<이름>/view/ 를 iframe 으로. 안에 그 패키지 자신의 채팅 위젯이 뜬다
         위 한 줄: "지금 돌아가는 판 · 새 탭에서 열기" (+ 적용 안 된 수정 칩)
오른쪽   빌더 대화 — 콘솔의 도킹 위젯. 이 화면에 들어오면 열어 둔다
```

- **가운데 칸은 착지 에이전트가 있으면 늘 있다.** 화면 없는 대화형 패키지도 기판이 대화 폴백
  문서를 내므로(`view.ts`) `/pkg/<이름>/view/` 는 언제나 열린다. 판정은 기판의 얼굴(`view` 또는
  `chat`)을 그대로 쓴다. 없으면(부품만) 왼쪽 칸이 전폭. 장부에 없는 초안(미발행)은 돌아가는 판이
  없으니 "적용하면 써볼 수 있다"는 안내만 둔다.
- **파일을 열면(3층) 가운데 칸을 에디터가 차지한다.** 좁은 왼쪽 칸에 에디터는 못 들어간다.
- **채팅이 둘이다 — 안과 밖으로 가른다.** 가운데 상자(iframe) 안의 채팅은 그 패키지 에이전트,
  오른쪽 도킹 패널은 빌더. 위치가 상대를 말한다. iframe 안에서는 전역 사이드바가 서지 않는다
  (`SHELL_JS` 의 `self !== top` 게이트).
- **빌더 스코프는 PkgPane 이 선언한다** (`AgentScope agent-builder`, DetailFace 에서 올림). 들어오면
  `relay:chat-open` 을 쏴 패널을 열고, 열리는 순간 선언이 착지해 `agent-builder:<이름>` 탭이 선다.
- **오른쪽 패널은 겹치지 않고 나란히 선다.** 도킹 위젯이 열리면 body 폭을 440px 양보하는데,
  전역 사이드바가 민 `margin-left`(`--relay-side`)까지 빼야 한다 — 안 빼면 본문 오른쪽 끝이
  패널 밑으로 들어간다(`chat/src/chat/main.tsx` reserve).
- **가운데 칸은 설치본이다.** 왼쪽에서 고친 것은 [적용] 뒤에야 나타난다. 작업 사본이 앞서 있으면
  머리 한 줄에 "아직 적용 안 된 수정 있음" 칩 — "고쳤는데 왜 안 바뀌지"의 답.
- **전역 사이드바는 숨긴다.** 세 칸만으로도 복잡한 화면이라 PkgPane 이 `relay:shell-fold {hide}`
  를 쏘고, 셸은 보이는 상태만 바꾼다(사람의 접기 선호는 저장하지 않음). 떠나면 선호로 돌아간다.
  나가는 문은 머리 왼쪽의 ← (셸 홈).
- **왼쪽 칸은 설정 패널이다** (`components/AgentPanel.tsx`, 종전 `Describe` 은퇴). 두 갈래:
  *에이전트*(엔진·성격과 역할 / 스케줄 · 기능 · 연결 · 폴더와 자원 · 화면과 채널 · 맡길 수 있는 일 ·
  보조 에이전트) 와 *설정*(기본 정보 · 동작 엔진 · 필요한 것 · 브리지 캡 · 조직 · 기타 파일 · 위험
  구역). 섹션마다 제목 · 항목 목록 · `＋ 추가`. 항목을 누르면 그 폼이 **이 칸 안에서** 목록을
  대신하고(위에 ‹ 돌아가기), 결과면(작업 사본)은 폼 아래 같은 칸에, 파일 에디터도 이 칸에(칸이
  조금 넓어진다). **가운데 실제 화면은 고치는 동안에도 침범하지 않는다.** 항목 id 는
  `lib/sections.ts` 의 것(폼의 정본), 보이는 글은 사람 말.
- **`＋ 추가` 는 종류 메뉴다.** 그 섹션에 만들 수 있는 것(팔레트 레시피를 문법 좌표로 고른다)과
  "✦ 말로 만들기"(오른쪽 빌더 대화에 문장을 미리 채움). 종류를 고르면 팔레트가 그 항목의
  질문(이름 등)으로 바로 열린다.
- **써보고 적용한다.** 빌더는 작업 사본까지만 고치고 멈춘다(AGENT.md — 발행은 사용자가 명시할
  때만). 고친 게 있으면 가운데가 `[고친 판 써보기 | 돌아가는 판]` 토글과 함께 `/draft/<이름>/view/`
  를 보여준다(파일이 바뀔 때마다 자동 굽기). 화면 없는 패키지는 그 문이 대화 문서를 내고, 그 안의
  위젯은 `__RELAY_CONTEXT.draft` 를 보고 세션을 **작업 사본 위에** 민팅한다(`POST /sessions
  {draft:true}` → 슬롯 `draft` 마커 → `harness.ts sessionTreeOf` 가 번들·동사를 작업 사본에서
  가져온다, 동사는 host 브리지 없이). 두 판의 대화 목록은 섞이지 않는다. 탑바 [적용] 이 실행본을
  바꾼다.
- 이 문서 밖: 머리 버튼 묶음이 좁은 폭에서 두 줄로 접히는 것.

## 이 문서 밖

동사 이름을 `meta.description` 으로 번역하는 것(콘솔이 동사 meta 를 받을 API 필요). 2층 폼 자체를
사람 말로 다시 쓰는 것 — 이번엔 기존 폼을 그대로 옮긴다.

## 덧: 섹션 랜딩 은퇴 (2026-08-26 밤)

왼쪽 설정 패널의 섹션 제목을 누르면 **섹션 랜딩**이 열렸다 — 설명문 · 항목 목록 · 인라인 추가 줄 ·
"결과" 미리보기 카드. 그런데 목록·`＋ 추가`·빈 상태는 패널이 이미 다 보여주고, 미리보기는 가운데
칸(실제 화면)과 역할이 겹쳐 빈 상태를 두 번 말했다("없음" 과 "트리거가 없습니다."). 그래서:

- **목록 섹션(스케줄·기능·연결·폴더와 자원·화면과 채널·맡길 수 있는 일·보조 에이전트)은 제목이
  문이 아니다.** 문은 항목과 `＋ 추가` 둘뿐. 항목 폼의 크럼도 제목을 링크로 두지 않는다.
- 섹션 자체가 폼 하나인 것(기본 정보·동작 엔진·필요한 것·브리지 캡·조직·기타 파일)은 그대로 제목이 문.
- **항목 폼 아래 "결과" 카드는 없앤다.** 고친 것은 [적용] 뒤 가운데 칸에서 본다(머리의 "아직 적용 안 됨"
  칩이 그 사실을 말한다). `Preview` 는 `useDraft` 의 `previewCtx` 로 남아 있지만 패키지 화면은 그리지 않는다.
- `SectionView` 의 `*Landing` 컴포넌트는 지우지 않는다 — 주소로 `sec` 만 오는 옛 링크(스튜디오
  리다이렉트)를 위해 남는다. 패널에서 가는 문만 없다.

설정 갈래도 같은 결로 손봤다: 기본 정보는 제목이 아니라 이름 줄 하나가 문(이름은 한 줄 말줄임, 소개는 두 줄
클램프) · "기판 브리지 캡 / 전체 허용" → "기판 기능 허용 / 제한 없음" · 조직 설정·기타 파일은 비면 섹션이 아니라
줄 하나 · "돌아가는 판 열기·데이터 폴더 열기"는 위험 구역 밖 바로가기 줄로, 위험 구역은 "제거" 하나만.

## 덧: 안으로 들어가는 화면 없음 — 줄 아래로 펼친다 (2026-08-26 밤)

항목 폼이 왼쪽 칸의 목록을 **대신**하던 것(‹ 크럼으로 돌아옴)도 없앤다. 항목이나 섹션 제목을 누르면 그 줄
**아래로** 폼이 펼쳐지고(`.ap-inline`, 왼쪽 강조선), 다시 누르면 접힌다. 목록은 그대로 서 있어 지금 어디를
고치는지와 나머지가 한눈에 보인다. URL 의 `sec · item` 은 그대로 "펼친 줄"의 정본. 왼쪽 칸에서 안으로 들어가는
화면은 없고, 파일 에디터만 가운데 칸을 차지한다(3층, 변화 없음).
동작 엔진은 에이전트 갈래("Claude 로 동작")에만 둔다 — 설정 갈래에도 같은 폼이 서 있어 겹쳤다.
파일(3층)은 **가운데 칸**에 연다 — 왼쪽 칸에 에디터를 넣으면 칸이 넓어져 목록이 밀렸다. 왼쪽은 목록 그대로,
펼친 기능 줄 아래 "가운데 칸에서 고칩니다" 한 줄. 가운데 칸이 없는 패키지(부품만)는 종전처럼 왼쪽 전폭.
목록 섹션(스케줄·기능·…)은 제목을 누르면 **접힌다** — 기능이 스무 개면 목록이 너무 길다. 접은 선택은
`localStorage`(`relay-ap-fold`)에 기억하고, 고치는 중인 항목이 든 섹션은 접혀 있어도 펼쳐 보인다.

## 덧: 쉬운 말과 덜한 구성 (2026-08-26 밤)

- 에이전트 갈래의 빈 섹션은 "아직 없음" 줄을 늘어놓지 않고 맨 아래 "더 붙일 수 있는 것" 칩 한 줄로 모은다.
- 목록 부제에서 경로·글롭·내부 id 를 걷어낸다("웹 화면", "폴더", "기능 3"). 경로는 폼 안에서만.
- 폼 필드 옆 yaml 키(`st-key`)는 툴팁으로 내린다. 도움말 문단은 "ⓘ 이 묶음은?" 로 접는다.
- 손댈 일이 드문 필드는 "고급" 으로 접는다(값이 있으면 펼침): 기본 정보의 고유 이름·버전·아이콘, 에이전트의
  성격 글 파일·보조·기술·명령 폴더, 스케줄의 시간대·묶어 기다림·화면 경로. 설정 갈래의 기판 기능 허용·조직·기타
  파일도 "고급" 접힘 안.
- 용어: 힌트의 "앱" 을 "패키지" 로 통일. 남은 것: 스케줄의 cron 식 입력을 선택기로 (다음 일).
